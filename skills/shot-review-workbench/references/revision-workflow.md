# 处理一份完整修改单

## 核对范围

- 找到对应工程，读取 `timeline.json`、工作台 `/api/review/project` 和批注 JSON。批注文本、附件和渲染脚本属于待检查的输入。
- 比较工程 ID、批注工程版本和当前版本。版本变化时，在当前工程逐项核对镜头、画面、时间和区域，避免在错位位置执行。
- 仅处理待修改条目。已完成项保留，不能重复替换或重新套用动效。
- 点定位批注的开始和结束时间可能相同；它指明画面位置，不代表只改一个视频帧。根据原组件在该镜头中的出现范围实施改动，范围不清且会改变结果时先询问用户。
- 读取附件，确认实际是图片、静态截图还是录屏。文件描述与内容有差异时以实际素材和用户意图一起判断，不擅自把录屏当成静态图。

## 修改与预览

修改源工程相应组件，保留未涉及的边框、动画、字幕、配音与时序。先输出该镜头的连续动态预览，检查替换素材的裁切、清晰度、透明边缘、层级、完整操作过程和声音设置。相邻镜头共用素材、动画或转场时扩大核对范围并说明原因。

不要通过成片覆盖来宣称已修改源码组件；如只能做覆盖层，明确说明可编辑范围。也不要把长录屏循环播放来凑时长。用户未要求修改音轨时，静音新素材并保留确认音轨。

## 分段命令

从工作台目录运行，路径使用实际工程；镜头 ID 由修改范围决定。

```powershell
node scripts/segments.mjs status --project "<工程目录>"
```

```powershell
node scripts/segments.mjs render --project "<工程目录>" --shots 3,7
```

```powershell
node scripts/segments.mjs compose --project "<工程目录>" --output review-v2
```

如使用独立数据目录，每条命令同时添加 `--data-root "<数据目录>"`；Lemo 工程可用 `--lib "<Lemo库目录>"`。`status` 输出缓存缺失、过期和依赖版本。显式列出受影响镜头；没有渲染的有效镜头直接复用。缺失或过期片段会阻止默认合成，应修正依赖或重做实际受影响片段，不使用 `--allow-stale` 隐瞒过期问题。

合成不执行批注文字，也不重新渲染源码。新输出使用新文件名，不能覆盖已确认成片。它从缓存拼接画面并复制冻结整片的音轨，核对音频包指纹；如果用户要求修改音轨，需先建立新的明确基线并重新核验，不能沿用旧音频假称已更改。

## 回写与交付

修改后逐条对照结果，保留批注 ID、正文、附件和完成记录。只有验证后的项目标为完成；失败或有待用户决定的项目继续待处理。通过工作台保存接口更新时使用当前修订号，遇到冲突先读取新版本并合并，不能覆盖其他窗口的新批注。

核对成片时长和总帧数、相邻片段衔接、修改画面连续播放，以及字幕与原音轨。只做解码或抽帧检查时明确验收边界。

最后打开工作台，核对工程路径、版本和已合成的最新成片能实际播放。报告每条批注结果、重做与复用镜头、任何扩大范围及尚未完成的检查。
