# 分镜批注工作台

让用户在可播放的工作台里指出“哪一镜、哪一刻、哪一区域、换成什么”，再据此修改源工程。工作台保存批注和素材；AI 或制作者执行改动，合成按钮不会自动理解文字批注。

## 准备工作台

本 skill 只包含操作规程和定位脚本，不携带工作台、视频或渲染器。先运行：

```powershell
node "<skill目录>/scripts/workbench.mjs" locate
```

脚本检查显式 `--home`、环境变量 `SHOT_REVIEW_WORKBENCH_HOME`、当前目录及其工作台子目录、skill 所在仓库和用户目录中的工作台。找到后输出工作台位置和实际 Git 提交；不会启动服务或更新已有目录。未找到且用户已要求安装工作台时运行：

```powershell
node "<skill目录>/scripts/workbench.mjs" clone --home "<工作台目录>" --ref main
```

获取代码与执行工程是两个步骤。阅读该副本 README，确认 Node.js、FFmpeg、FFprobe 等依赖及本次要运行的工程。不要把工作台地址或私人工程路径硬编码进 skill。

## 建立可返修的影片

先读 [工程格式](references/project-format.md)。为镜头使用固定 ID、全局帧区间和独立源文件，保存真实依赖、分段视频及已确认音轨。保持工程时间线连续；当前引擎要求 1920×1080、30fps。

新工程应能独立重渲染指定镜头。已有成片可先迁移成分段缓存供审片，但迁移不等于还原了组件或独立源码。不要反复播放同一片段、重置同一套入场动画来填充时长；关键帧只确定视觉方向，不限制正式镜头数量。

## 交给用户批注

1. 设置 `VIDEO_PROJECT_ROOT` 指向本次工程，使用独立端口和数据目录启动工作台。项目切换后重新核对 `/api/review/project` 中的工程路径、版本、镜头和最新整片。
2. 打开工作台，确认可播放。告诉用户：选镜头 → 暂停定位 → 圈选区域 → 写要求、附图片或录屏 → 保存批注 → “复制全部批注”。需要指定区间时填写开始和结束时间。
3. 保留已完成批注供核对。用户把修改单发回后，按下节处理；不把附件名或批注文本直接执行为命令。

## 按批注返修

读 [返修规程](references/revision-workflow.md)。先核对工程 ID、批注版本、当前版本、全局帧和附件。版本不同先对照当前画面，不能照搬旧时间码。只处理待修改条目；定位点表示要检查的画面，改动范围仍取决于用户要求与该组件实际存在的时间。

修改指定镜头和区域，保留未提到的文案、字幕、音轨、镜头与总时长。若共享素材、连续动画或转场会影响邻段，先说明实际范围；改变时长前明确后续字幕与音轨的处理。不要通过忽略依赖或强行复用过期缓存掩盖影响。

局部动态预览确认位置、裁切、层级、时间和声音后，重渲染受影响片段，复用其余有效缓存，再合成整片。只有逐条核对完成，才更新对应批注状态；保留批注 ID 和内容供复查。

## 完成交付

每次制作或返修视频完成后，打开“分镜批注工作台”，确认加载当前工程和最新成片。检查受影响片段的连续播放、邻段衔接、全片时长、字幕和音轨。技术解码或抽帧通过不能代替动态观看，也不能代替试听；如未完成某项检查，明确告知。

交付新版 MP4、更新后的源工程及逐条处理结果，说明重做与复用范围。工作台和 skill 可按用户要求发布；本 skill 本身不授权公开私人素材、批注或工程。
